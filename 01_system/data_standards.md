# Data standards

Keep records human-readable and consistent. Do not introduce a complex schema unless it becomes necessary.

## General conventions

- Markdown (`.md`) is the default format.
- Use UTF-8.
- Use lowercase, hyphen-separated filenames.
- Use ISO dates: `YYYY-MM-DD`.
- Use full source URLs, not search-result URLs where a direct page is available.
- Include a `Last checked` or `Last verified` date when a record or fact is reviewed.
- Use `Not yet checked`, `Unknown` or `Not published` rather than guessing.
- Distinguish an official source from a secondary source.

## Evidence labels

Use plain language labels:

- **Verified**: supported by a current, relevant source.
- **Partially verified**: some details are supported; other details remain uncertain.
- **Unverified lead**: worth investigating, but not confirmed.
- **Outdated**: was once supported but needs a fresh check.
- **Not found**: not located after a documented search; this does not prove it does not exist.

## Pricing and access

Do not reduce access to a simple free/paid assumption. Record the actual condition, for example:

- Free entry, no registration stated.
- Free, registration required.
- Free ticket, limited capacity.
- Ticket lottery.
- Paid.
- Mixed programme; varies by event.
- Not yet verified.

## Event dates and times

- Use the local event date and time as published.
- Assume Madrid local time only when the event is in Madrid and no conflicting timezone is indicated.
- Do not infer an end time.
- Mark tentative announcements as tentative.
- Recheck time-sensitive details before producing an agenda.

## Linking

Use relative links between repository files where practical. Always retain the original external event URL in event findings and outputs.

## Updating

When new research changes an existing fact, update the entity record and note the source and date. Keep dated schedule checks and AI outputs as historical records.
